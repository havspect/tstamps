# Agent skills live in their own repository, as a plugin

The `tstamps` agent skill is published from `havspect/tstamps-skills` as a plugin: a root `plugin.json`, the skill at `skills/tstamps/SKILL.md` with its `mcp.json` and `references/`, and an `apm.yml` carrying `dependencies: {}` so `apm pack` emits a plugin bundle. Amp installs the same directory with `amp skill add havspect/tstamps-skills/skills/tstamps --global`.

Why: this repo's root already holds `.agents/skills/` — our own development skills, pinned in `skills-lock.json` — so pointing an agent install at it would ship those too. A plugin repository keeps the installed thing small, installable without cloning an AGPL Go project, and releasable between binary versions, and the plugin layout is what makes `apm pack` produce a bundle and what `apm install` and `gh skill install` deploy into `.agents/skills/` for the harnesses that read it.

Considered options: `skills/tstamps/` in this repo (rejected: mixes the skill's tool names with the server's CI to save one clone, and installs the development skills along with it); a top-level `tstamps/` instead of `skills/tstamps/` (rejected: not a plugin layout, so `apm pack` cannot produce a plugin and Claude plugin hosts cannot install it); separate skills for the calendar and history workflows (rejected: Amp hides a skill's `mcp.json` tools until that skill loads, so each workflow skill would either redeclare the `tstamps` server under the same name or need the main skill loaded first).

Distribution uses Microsoft's APM (`microsoft.github.io/apm`; the unrelated registry at `apm.orthg.nl` shares the name and is not this). `apm pack` packs `plugin.json` plus `skills/tstamps/` and an embedded `apm.lock.yaml`, which is committed; `apm install <bundle>` deploys all four skill files, `mcp.json` included, into `.agents/skills/tstamps/`. `amp skill add` with the subdirectory path is the lighter route for Amp users, and `gh skill install` covers Claude Code, Codex and OpenCode.

Consequence: renaming an MCP tool or changing a default on this side will not fail the skill repo's CI, so the skill does not enumerate tool names — its `mcp.json` omits `includeTools` and its prose describes behaviour rather than `start_timer`. The README of the skill repo states the minimum `tstamps` version instead of pinning one. `mcp.json` is read by Amp only: a harness without it needs `tstamps mcp` configured in its own client, as the manual already describes, and the skill repo's client pages say so.
